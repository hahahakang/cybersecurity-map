“安全地运行 Agent”行业图谱：三级细分与功能点、中国市场规模与 C 端推演

主轴按“产品类型＝客户需求”划分 5 个三级细分、下设 16 个三级细分功能点；给出各三级细分中国 2025 / 2030 规模与 CAGR（以 IDC 权威总盘为锚、分项为行业测算）；并以必要条件法推演能否出现 360 式 C 端流量入口巨头。

核心结论：①本二级划分为 5 个三级、16 个功能点；②中国市场权威总盘为 IDC“人工智能安全”2025 年 44.1 亿 → 2030 年 340.3 亿元、CAGR 50.5%，以其为锚的分项行业测算：运行时防护(T4) 18.5→148 亿元、体量最大，智能体身份(T3)增速最快；③148 亿不是天花板——智能体大盘以 CAGR≈70.9% 增长，安全支出＝大盘×渗透率，大盘联动重估下 T4 细分市场 2030 实为 100–310 亿元、智能体安全总盘 240–700 亿元（详见第四节）；④行业头部专家观点一致指向 harness / 运行时防护是共同卡点、价值在“控制面＋数据飞轮”而非模型（详见第五节）；⑤360 式“免费安全→C 端流量入口→全新商业模式”在本细分不成立，根因是“买方结构”与“入口位置”双重反转，独立巨头的现实路径在 B 端运行时 + 身份的数据飞轮，而非 C 端流量。

〇、细分行业概述

开篇概述：①行业定义 → ②产品解构（核心组件 / 核心控制参数）→ ③应用场景 → ④发展阶段 → ⑤过去若干年规模与增速 → ⑥相对国外领先产品的差距、瓶颈。

① 行业定义

“安全地运行 Agent”指：为智能体（Agent）在执行多步、带工具权限、自主决策的任务全生命周期提供安全能力的软件产品与服务的集合——即智能体的“运行时安全带 / 控制面”（Harness）。守护对象是“会自己干活、有工具、有数据权限”的 Agent，而非“只会对话”的聊天模型。

  • 守护什么：防止 Agent 被 Prompt 注入、越权调用工具 / API、MCP / Skill 供应链投毒、敏感数据外泄、被“洗脑”执行恶意指令等。
  • 行业边界（Securing AI）：本行业属于“守护 AI / 让 AI 安全运行（Securing AI）”一侧；与“用 AI 做安全（AI-amplified Security，AI 赋能安全运营）”是并列的两侧，不合并计算。
  • 层级结构：大行业“人工智能安全（Securing AI）”下，按产品类型（客户需求）划分本二级细分，下设 5 个三级（T1 治理态势 / T2 上线前测试 / T3 智能体身份 / T4 运行时防护 / T5 检测守护）与 16 个三级细分功能点（详见第二、三节）。

③ 应用场景

  • 金融 / 政务 / 运营商 / 能源电力 / 制造：企业部署自主 Agent（智能客服、数据查询、代码生成、邮件与审批处理、交易辅助）时，防止越权工具调用、敏感数据外泄、Prompt 注入。
  • 供应链安全（标志性事件）：2026-01 OpenClaw“利爪浩劫”（ClawHavoc）——迄今最大规模 AI 智能体供应链攻击，暴露 Skill / MCP 生态投毒风险，直接催生运行时防护刚需。
  • MCP / Skill 审查：Agent 调用第三方工具前的供应链体检（对应 T2 上线前测试 + T4 运行时双重覆盖）。
  • 合规审计：智能体强制国标《智能体应用安全基本要求》2026-06 立项、网安标委“人工智能安全标准工作组（WG9）”组建，驱动审计与态势管理采购。
  • 个人侧（当前非主流）：保护个人免受 AI 伤害（反深伪 / AI 鉴真 / 反诈）正被 OS、国家、平台三方内化为准公共品，不构成独立第三方大市场（详见第十节推演）。

④ 发展阶段

导入期 · 2023–2024
大模型爆发 → LLM 安全（护栏 / 评测）萌芽，以“模型层”为主，Agent 尚未规模化。
成长期 · 2025–2026（当前）
Agent 化落地 → 威胁焦点从模型层转移到运行时与供应链；“利爪浩劫”敲响警钟；强制国标立项。
扩张期 · 2027–2030
企业级标准与信任体系成熟 → 渗透率抬升；Gartner 全球 2030 $164 亿、中国 IDC 2030 340.3 亿。

中美格局差异：美国为资本风投驱动 + 平台化整合（Check Point 收购 Lakera、Cisco 收购 Astrix，独立厂商被巨头吸纳）；中国为监管合规驱动 + 垂直行业深耕（强制算法备案、AIGC 内容标识、智能体安全国标）。

三、16 个三级细分功能点：逐一说明“是什么、防什么”

每个三级细分下设若干功能点，共 3+3+3+4+3 = 16 个，彼此不重叠。

T1 治理态势（3 个）
1.1 资产发现与影子 AI：自动盘点模型 / Agent / MCP / Skill / RAG，明确责任人，清除未登记影子智能体。
1.2 风险态势 / AI-BOM / 合规：组件清单与风险打分，映射 NIST AI RMF、EU AI Act、ISO 42001 与国内监管。
1.3 策略与治理工作流：统一策略基线、分级审批、例外与整改闭环（管理平面）。
T2 上线前测试（3 个）
2.1 自动化红队 / 对抗测试：批量生成注入 / 越狱 / 多轮渐进攻击探针，CI/CD 门禁化评分。
2.2 模型制品安全扫描：检测模型文件后门、投毒、篡改与窃取风险。
2.3 MCP/Skill 供应链审查签名：第三方工具 / 插件上架前审计、AI-SBOM 与数字签名。
T3 身份权限（3 个）
3.1 NHI 生命周期：为每个 Agent 签发 / 变更 / 回收非人身份（“数字工牌”）。
3.2 最小权限与委托链：父子 Agent 权限逐层收缩、时限授权、人-机 / 机-机授权。
3.3 特权访问与凭证防护：PAM for Agents、凭证不落地、环境绑定、UEBA 异常基线。
T4 运行时防护（4 个）
4.1 护栏 / LLM 防火墙：拦截直接 + 间接提示注入、越狱与有害输出。
4.2 工具调用行为管控：逐次工具调用“允许 / 阻断 / 转人审”，防目标偏离。
4.3 Agentic DLP：防 Prompt / 上下文 / 工具参数中的敏感数据外泄。
4.4 执行沙箱隔离：代码执行隔离、网络 / 文件系统白名单，限制爆炸半径。
T5 检测监督（3 个）
5.1 轨迹可观测与审计：思维链 / 工具链 / 子 Agent 全链路 Trace、100% 可审计、对接 SIEM。
5.2 AIDR / 级联熔断：多步行为偏离基线告警、多 Agent 级联失效熔断与自动处置。
5.3 守护智能体：用 Agent 以机器速度 7×24 评估、约束其他 Agent（Gartner 独立品类）。

十、关键推演：会出现 360 式“安全→C 端流量入口”新商业模式吗？

方法：先还原 2009 年 360 模式成立的必要条件，再逐条对照 2026 智能体时代检验，最后给出结论与跟踪触发条件。

第一步 · 还原 360（2009）模式的 7 个必要条件。360 的本质不是“卖杀毒”，而是用免费、全民、高频的安全做钩子获取 C 端流量，再导流到浏览器 / 导航 / 应用分发，用搜索广告与游戏联运变现——安全本身不赚钱，流量入口才赚钱。成立需同时满足：C1 需求全民化；C2 高频可感知；C3 产品标准化零边际成本；C4 存在可被免费颠覆的付费在位者；C5 安全占据设备级咽喉、可自然导流高频应用；C6 下游存在巨大可变现流量市场；C7 规模 / 数据飞轮。
必要条件2009 PC 互联网（360）2026 智能体时代（本细分）是否成立
C1 需求全民化，TAM=全体网民每台 PC 都会中毒，人人需要杀软“守护 Agent 运行”的买方是部署 Agent 的组织；个人并不运营 Agent 舰队，无“我的 Agent 被注入”的全民痛点不成立
C2 高频、可感知、强留存中毒 / 卡顿频繁，用户能直接感知个人侧 Agent 被攻破低频且不可见；安全是“装完即走”，打开率极低不成立
C3 标准化、零边际、自助化一次下载全民通用技术上可标准化，但失去 C1/C2 则无流量意义技术成立、商业无意义
C4 有可被“免费”颠覆的付费在位者瑞星 / 金山收费且体验差，免费制造病毒式替代C 端根本不存在付费的“个人 Agent 安全”品类，免费没有颠覆对象、没有被迫迁移不成立
C5 安全占据咽喉、可导流高频应用杀软驻留开机 / 内核 / 网络层，顺势捆绑浏览器、hao.360 导航用户直达 ChatGPT / 豆包 / 超级 App；第三方护盾只能做重且低意愿的 VPN 代理或套壳，站不到用户与 AI 之间，无法导流不成立（最致命）
C6 下游有可变现大流量市场搜索 / 导航 / 应用分发处于红利期，存在信息差租金消费流量已被腾讯 / 字节 / 阿里 / 百度寡头化且正被 AI 搜索重构；Agent 直接给答案，“导航页租金”被消灭；安全 App 无内容 / 交易面承接广告不成立
C7 规模 / 数据飞轮用户越多病毒库越强、流量广告议价越高攻防数据飞轮真实存在，但在企业侧沉淀为更好的 B 端产品；C 端反诈数据掌握在平台 / 银行 / 运营商 / 政府手中，第三方拿不到仅 B 端成立
第二步 · 找出最根本的两条结构性反转（推理链的“题眼”）。
反转一 · 买方结构反转：PC 时代安全的受害主体与使用主体是亿万个人（C 端天然成立）；智能体时代，能“运行 Agent、拥有工具与数据权限、一旦失控造成损失”的主体是企业 / 机构，付费方天然是 B / G 端，个人没有可保护的 Agent 资产。
反转二 · 入口位置反转（更关键）：PC 时代浏览器是用户上网的独立入口、且操作系统（Windows）在中国不提供可信安全，360 得以前置于浏览器占据咽喉；智能体时代，流量入口上移为“模型 / Agent 本身”（它就是新浏览器），安全退居入口的下游——一个下游护栏不可能反过来导流、更不可能成为入口。要当入口，安全公司必须自己成为消费级 Agent，那已是与 OpenAI / 字节 / 腾讯 / Apple 正面竞争的另一门生意，“安全”只剩获客卖点，不是商业模式。
第三步 · 检验唯一可能的 C 端候选路径（Steelman，不回避）。最像 C 端机会的是“保护个人免受 AI 伤害”：反深伪语音 / 视频、AI 鉴真、家庭反诈、个人 Agent 身份钱包。但证据显示该层正被三股力量内化为准公共品 / 平台内置功能，不给独立第三方留流量入口：
  • OS / 终端内置：苹果端侧处理 + iOS 26 通话风险识别、vivo OriginOS 离线反诈、华为鸿蒙 AI 防窥；
  • 国家免费供给：国家反诈中心 App 上线“AI 内容鉴定”、TC260 发布《个人用户使用人工智能服务安全指南》；
  • AI 平台自我兜底：OpenAI Advanced Account Security、Google SynthID / C2PA（已为超 1000 亿条生成内容打水印、Gemini 内鉴真超 5000 万次）；
  • 独立创业如家庭反诈 Savi Security 仅融资 700 万美元、属小众工具，不具备流量入口相。
结论：在“安全地运行 Agent”细分内，360 式“免费安全 → 占领 C 端流量入口 → 全新商业模式”不成立。七条必要条件中 C1/C2/C4/C5/C6 五条不成立、C3/C7 仅在 B 端成立；根因是买方结构与入口位置的双重反转。独立安全巨头的现实路径在 B 端：以 T4 运行时防护 + T3 智能体身份为支点，靠攻防数据飞轮成为 AI 时代“安全底座 / 智能体流量的安全清算层”，以 License 订阅 + 涉密 / 国防 B2G 变现，赢家通吃，而非 C 端广告流量。
结论的跟踪触发条件：需 F1、F2 同时成立——F1：个人 Agent 大规模普及（每个网民都有可代己交易 / 操作的私人 Agent），且 OS 与超级 App 因反垄断 / 碎片化不提供统一安全层，催生“中立第三方个人 Agent 运行时 + 身份钱包”刚需；F2：某安全厂商能把防护做成个人 Agent 的默认承载层（即自己成为个人 Agent 入口 / 信任 OS）。届时它本质已是消费级 Agent / 身份超级 App，须具备 C 端产品与生态基因并正面对抗 Apple / 字节 / 腾讯 / OpenAI，概率低。截至 2026 年的全部证据（OS、国家、平台三方内化）均指向相反方向，故当前判断为“不成立”，并持续以 F1/F2 作为跟踪信号。
